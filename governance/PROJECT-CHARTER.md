# ProjectLubyanka 최상위 기획 정본

루비얀카의 목적은 개발을 맡은 AI가 개발자의 요구를 임의로 줄이거나, 확인하지 않은 결과를 완료로 보고하는 일을 막는 것이다. 개발자가 목적과 요구를 정한다. 이 문서는 그 지시에 따라 프로젝트의 범위와 문서 위계를 정한다.

## 문서 위계

최상위 기획 정본은 하나다. 코드 규칙, 인프라, 각 하위 방법론도 담당 범위마다 유효한 정본을 하나씩 둔다. 하위 문서는 상위 지침 안에서 해당 분야의 실행 방법을 정한다. 같은 사항을 다른 문서에서 인용할 때는 정본을 가리킨다.

| 다루는 사항 | 기준으로 읽을 문서 |
| --- | --- |
| 프로젝트 목적·범위·문서 위계 | 이 문서 |
| 개발 절차와 샤라시카 필수 시험 | [방법론 정본](LUBYANKA.md) |
| 요구별 입력·기대값·필요한 증거 | [프로젝트 정답지](../lubyanka-oracle.json) |
| 실제로 놓친 가정·교정·재검증 | [프로젝트 자아비판문](../LUBYANKA-SELF-CRITIQUE.md) |

## 문서를 만들고 바꾸는 순서

1. 프로젝트를 시작할 때 목적과 범위, 근거가 되는 개발자 지시를 먼저 적는다. 기존 프로젝트에서는 해당 정본을 찾아 읽는다. 필요한 문서가 비어 있으면 확인한 지시와 원문으로 채운 뒤 본 작업에 착수한다.
2. 새 지시가 오면 바뀌는 사항을 담당하는 정본을 찾는다. 최초 원문과 후속 정정을 보존한다. 제안이나 메모를 채택할 때는 어떤 개발자 지시를 반영했는지 적는다.
3. 변경할 조항을 상위 지시와 대조한다. 하위 조항이 명확한 상위 지시와 충돌하면 하위를 고친다. 개발자 지시만으로 결정할 수 없으면 충돌한 두 조항을 기록하고 그 결정에 의존하는 작업을 보류한다.
4. 조항이 바뀌면 이를 참조하는 문서, 정답지, 검증 절차를 함께 점검한다. 변경 이력은 Git에 남긴다.

## 공용 패키지와 바사리

ProjectLubyanka 전담 세션이 공용 코드·정본·배포를 맡는다. 현재 사용 앱은 바사리아트워크 하나다. 바사리는 공식 npm 공개본을 설치하고 제품별 규칙·시나리오·기대값을 바사리 저장소에서 관리한다. 공용 변경 요청과 결함은 건마다 ProjectLubyanka에 전달한다. 패키지의 브랜치·공개 절차는 [방법론 정본의 배포 조항](LUBYANKA.md#패키지-개발과-사용-앱의-설치)을 따른다.
