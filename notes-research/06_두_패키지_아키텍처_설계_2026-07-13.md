## §0. 한 장 요약 — 두 패키지는 근본적으로 다른 물건이다

| 축 | **① 루비얀카 패키지** | **② 레드팀 패키지** |
|---|---|---|
| 한 줄 | 루비얀카 방법론을 실천하는 **설치형 하네스** | 완성물을 예측 못 하게 공격하는 **독립 배포 게이트** |
| 형태 | **플러그인/패키지**(Claude Code 플러그인 + npm/PyPI) | **외부 CI 서비스**(GitHub App/봇) — **플러그인 아님** |
| 위치 | 프로젝트 **안에 설치**(INTO) | 모든 프로젝트 **밖에 독립**(OUTSIDE) |
| 시점 | **개발 중** (짓는 동안) | **배포 관문 4지점** (dev 전/후, main 전/후) |
| 대상 | 나(개발자)가 AI를 취조하도록 도움 | "프로젝트를 만진 세션·문서·에이전트·하네스·센서"를 피의자로 |
| 권한 | 조언·검증 게이트 | **배포 중지 / 롤백 명령**(파이프라인 권한) |
| Ouroboros 대비 | 소크라테스식의 **적대적 짝** | Ouroboros엔 없는 **고유 발명** |
| 진화 | 방법론 업데이트 | **자기학습 + 연구·전문가(파울러) 주기 반영**(화이트리스트+사람승인) |

**동기(둘 다 같은 뿌리)**: Doc1 §5에서 실측한 것 — Grimoire 자기감사가 "센서 56개 중 30개가 수천 번 돌며 0회 실패, 방어 5겹 중 3겹이 빈 파일"을 적발. 프로젝트 *안에* 사는 레드팀·센서는 무시되거나 썩는다. 그래서 방법론은 설치형으로(①), 감시자는 **밖으로 독립**시켜(②) 무시 불가능하게 만든다.

## §1. 두 패키지가 공유하는 4대 원리

1. **BYO-키(각자 자기 키) — 저자는 0원.** 패키지는 **쓰는 사람 기계/CI에서 돌고, 그 사람 API 키로 그 사람 LLM을 부른다.** 저자(사용자)를 거치지 않는다. Ouroboros가 그 증명 — 로컬 우선(local-first), `.env`의 `API_KEY`는 사용자 것. (유일 예외: ②를 *호스팅 SaaS*로 돌릴 때 → §3.6.)
2. **결정론 우선 — 토큰 절약.** 검증의 대부분("테스트 재실행·curl·파일 크기·속성 테스트")은 **LLM 없이 공짜**. LLM은 소수 판단에만, 필요할 때만 계층 상승. Ouroboros PAL Router: Mechanical(무료)→Semantic(1콜)→Consensus(2+콜, 실패 시만).
3. **코드가 아니라 명세에서 공격/검증한다.** 구현 코드를 읽으면 만든 사람의 가정을 물려받는다. 무엇을 *해야 하는가*(명세·계약·PRD)에서 검증을 도출해야 예측 못 한 것을 잡는다.
4. **상관된 맹점은 완전 극복 불가(정직).** Claude로 만든 걸 Claude로 검증하면 같은 사각을 공유한다. 완화 = 비-LLM 결정론 검사 + 다른 벤더 모델. "예측 못 한"은 *보장*이 아니라 *체계적 사각 축소*가 최대치(방법론 №006 "미완성" 자인과 정합).

## §2. 패키지 ① 루비얀카 패키지 — 설치형 방법론 하네스

### §2.1 정체
네 프로젝트 안에 설치돼, **개발 중에** 네가 AI를 루비얀카식으로 취조하며 짓게 돕는다. Ouroboros(소크라테스식: 짓기 전 면담→명세)의 **적대적 짝**(짓는 내내 자백 반증). 형태 = 플러그인/패키지.

### §2.2 3층 아키텍처 — "web/server/Android/iOS 다 통용"의 정체
크로스스택의 비결: **어디서나 같은 것(방법)과 스택마다 다른 것(측정 명령)을 분리.**

- **1층 · 방법 (어디서나 동일, 90%)** — 루비얀카 방법론은 인식론이라 언어 무관. 프롬프트·스킬·에이전트 정의·자백서(incident) 포맷·금지어 목록·검증 프로토콜로 인코딩(전부 마크다운/설정). **패키지의 뇌.**
- **2층 · 런타임 (어디서나 동일, 오케스트레이터)** — 방법을 실행하는 작은 프로그램. **네 앱을 컴파일하지 않고** 각 스택 도구를 불러 쓸(shell out) 뿐이라 **언어는 거의 무관**(§2.3). 취조 절차 구동·LLM 호출·검증 명령 실행·자백 로깅.
- **3층 · 어댑터 (유일하게 스택별, 10%)** — 방법의 추상 동사를 스택별 명령으로:

| 추상 동사 | web(Next) | server(Nest) | Android(Gradle) | iOS(Xcode) |
|---|---|---|---|---|
| `verifyBuild()` | `npm run build` | build | `./gradlew assemble` | `xcodebuild build` |
| `runTests()` | vitest/playwright | jest | `./gradlew test` | `xcodebuild test` |
| `checkDeploy()` | `curl /health` | health endpoint | 에뮬 설치·구동 | 시뮬 구동 |
| `measureState()` | 파일 존재·엔드포인트·DB 행수 | 〃 | 〃 | 〃 |

코어는 `adapter.verifyBuild()`만 부르고 밑을 모른다. **새 스택 = 어댑터 하나 추가, 방법 불변.** 이게 "통용되는 구조."

### §2.3 자동 감지 + 배포 채널 + 런타임 언어
- **자동 감지(brownfield)**: 설치 시 스캔 — `package.json`→web/node, `build.gradle`→Android, `*.xcodeproj`→iOS — 어댑터 자동 선택. **경로 하드코딩 금지**(Grimoire 71/81 실수).
- **런타임 언어 = 배포 채널·청중이 결정(정직).** 오케스트레이터라 언어는 거의 무관. 후보: Python+PyPI(AI 도구 기본값, 최광범위) / Node+npm(웹·서버 친숙, 네가 만들기 쉬움) / **Claude Code 플러그인(언어 중립 — 밑이 뭐든 무관)**. **권장: 플러그인을 1차 채널**(청중이 Claude Code면 런타임 고민 소멸), 코어 언어는 빌드 편의로. (Ouroboros는 플러그인+PyPI 둘 다.)
- **설치**: `claude plugin install lubyanka@…`(+ 선택 `npm i -D lubyanka`) + 프로젝트별 `.env`/설정.

### §2.4 비용 모델
BYO-키(§1-1) + 결정론 우선(§1-2). 저자 0원, 사용자는 자기 키로 자기 사용분만. 취조의 상태 재측정은 대부분 무료, LLM은 소수 판단만.

### §2.5 이미 갖고 있는 것 (신규 빌드 최소화)
뇌(방법)와 기제층은 Grimoire에 있다 — `pretooluse-main-whitelist.sh` 토크나이저, gate→sensor→bounded-retry→incident-log, verifier 에이전트, honesty-audit(Doc4 §2.2). **없는 것: (a) 하드코딩 경로→어댑터/설정 추출 (b) 플러그인/패키지 껍데기.** Ouroboros가 이 모양이 배포된다는 산증인.

### §2.6 스캐폴딩(init) 능력 — 사용자 통찰(2026-07-13)
방법론의 골격(§0 율법·SSOT·피라미드 문서·프로그레스·핸드오버·에이전트 로스터·센서/게이트·incident 포맷·금지어)은 **프로젝트-무관 스켈레톤**이다 — 사용자가 8개 프로젝트에 같은 골격을 손이식한 것이 증거(Phase1). 그래서 패키지 ①은 `lubyanka init`으로 **구체 지시 없이도 골격을 자동 생성**할 수 있다 = 손 스캐폴딩의 자동화.
⚠️ **방법론 자신의 이론이 경계를 긋는다(이론편)**: 스캐폴딩은 **구조(스켈레톤)만** 생성하고 **실질(SSOT·도메인 진실·"무엇이 옳음")은 자동 채우면 안 된다.** 실질은 인간의 판단(인간편)이며, AI가 추측해 채운 SSOT는 곧 '그려진 문'(theater)이다. → init은 템플릿·스텁을 **비워** 깔고, SSOT는 인간이 채우거나 경량 인터뷰로 끌어낸다. **구조는 자동, 실질은 인간.** (Ouroboros가 spec-first로 이 균형을 이미 시연.)

## §3. 패키지 ② 레드팀 패키지 — 독립 배포 게이트 감시자

### §3.1 정체 — 플러그인이 아니다 (사용자 직감 확정)
플러그인은 호스트 *안에서* 돈다 = 독립 공격해야 할 대상 안에서 돈다 → 같은 사각 공유 + 프로젝트가 무시 가능(= 그 썩음). **독립 감시자가 프로젝트 안에 살면 독립이 아니다.** 그래서 ②는 **외부 서비스**(GitHub App / CI 통합 봇). 프로젝트는 *등록*만 하고, ②는 밖에서 파이프라인 권한으로 개입한다.

### §3.2 생애주기 — 4개 배포 관문
| 관문 | 시점 | 발견 시 명령 |
|---|---|---|
| G1 | dev 배포 **직전** | 배포 **중지** |
| G2 | dev 배포 **직후** | **롤백** |
| G3 | main 배포 **직전** | 배포 **중지** |
| G4 | main 배포 **직후** | **롤백** |

각 관문에서 "그 프로젝트를 만진 세션·클로드 문서·에이전트·하네스·스킬·센서가 **예측 못 한 방식**으로" 소스 동작·문서 상태·실제 배포를 공격.

### §3.3 "예측 못 한 공격" 5종 도구 × 3표적
원리: **구현 코드가 아니라 명세에서 공격을 만든다**(§1-3). 도구:
1. **속성기반 테스트(property-based, TS=`fast-check`)** — 불변식 선언 → 도구가 아무도 안 짠 입력 수천 개 생성해 깨려 듦. (예: "금액 ≥ 0" → 음수 만들 입력 만 개.)
2. **퍼징(fuzzing)** — 망가진·극단 입력으로 크래시 유발.
3. **차등 테스트(differential)** — 구현 vs 명세/독립 재구현 대조, 어긋나면 버그.
4. **다른 벤더 모델** — Claude 산출물을 Gemini/GPT로 공격(상관 맹점 축소).
5. **실제 상태 프로빙** — 라이브를 직접 때림(보안 헤더 실측·인젝션·경계값·동시요청 부하).

| 표적 | 공격법 |
|---|---|
| 소스 동작 | 명세에서 뽑은 속성기반/퍼즈/차등 테스트 |
| 문서 상태 | 문서 주장 vs 실측 대조(honesty-audit: "8종" 적힘→실제 3종) |
| 실제 배포 | 라이브 엔드포인트 프로빙(헤더·인젝션·경계·부하) |

대부분 **비-LLM 결정론**이라 토큰 0. LLM은 공격 케이스 생성·결과 해석 등 소수에만.

### §3.4 이빨 — 파이프라인 권한
"중지/롤백 명령"은 advisory여선 안 된다(advisory=무시=썩음). ②는 **CI/CD에 앉는다**:
- **G1·G3(중지)**: GitHub Actions **필수 상태 체크**(fail 시 머지/배포 차단) — 로컬 `--no-verify`로 못 넘는 서버측 게이트.
- **G2·G4(롤백)**: 배포 웹훅(Vercel/GCP 등) 수신 → 공격 실패 시 **롤백 트리거**(직전 배포로 되돌림) + 만진 곳에 사유 통보.
정중함이 아니라 파이프라인 권한이 이빨이다.

### §3.5 자기진화 거버넌스 (사용자 인정: 화이트리스트 + 인간 핸들링)
- **발견 학습**: 각 관문의 적발을 사례로 축적 → 다음 공격 강화.
- **연구·전문가 반영**: 최신 논문 + 마틴 파울러 등 전문가 의견을 **주기적으로** 흡수 — 단 **소스 화이트리스트**(OWASP·arxiv·martinfowler.com·지정 GitHub 등)로 인젝션 방어 + **사람 승인 게이트**(`proposals/` 통과 없는 자율 갱신 금지, Grimoire 패턴). 자기수정 구조적 차단.
- **감시자도 자기감사 대상**: ②도 never-FAIL·빈 파일로 썩을 수 있다 → honesty-audit을 **자신에게도** 정기 실행(Doc4 §6, Ouroboros=자기소비 뱀의 함의).

### §3.6 비용·호스팅
- **self-host(권장 기본)**: 각 조직이 자기 CI에 ②를 얹고 **자기 키로** 구동 → 저자 0원.
- **SaaS(선택)**: 네가 중앙 호스팅 → 네가 비용 부담 → 구독료 청구 모델. 사업 결정이지 기술 제약 아님.

## §4. 두 패키지의 관계 — Ouroboros 지형 위에서

```
         [Ouroboros = 소크라테스식]           [① 루비얀카 = 적대식]
         짓기 전: 면담→명세 정렬               짓는 중: 자백 반증(설치형)
                                                     │  같은 방법론, 개발 시점
         ───────────────────────────────────────────┤
                                                     ▼
                              [② 레드팀 = 독립 배포 게이트]
                              배포 4관문: 명세 기반 예측불가 공격
                              → 중지/롤백 명령(파이프라인 권한)
                              → 자기학습 + 연구/파울러(화이트리스트+승인)
                              프로젝트 밖, 무시 불가
```
①은 **네 손에 쥐는 도구**(설치형), ②는 **네 위에 앉는 심판**(외부 게이트). ①이 소크라테스의 짝이라면, ②는 아무도 안 만든 네 고유 발명 — Doc1이 실측한 "레드팀이 썩는 문제"의 구조적 해답.

## §5. 빌드 로드맵 (단계적·헛돌기 방지)

2026-11-23에 정리한 [자아비판 라이브러리 구현 계획](LUBYANKA-LIBRARY-PLAN.md)은 패키지 ①의 최신 전문 전달, 재독 조건, 호스트의 도구 제한, 검증 순서를 다룬다.

**패키지 ①**
1. 방법 인코딩(스킬·프롬프트·자백서 포맷) + **web 어댑터 1개** → 한 프로젝트에서 BYO-키로 구동(PoC).
2. 어댑터 확장(server·Android·iOS).
3. Claude Code 플러그인 포장(`.claude-plugin/plugin.json`) + 자동 감지 + `.env` 설정. (선택 npm/PyPI.)

**패키지 ②**
4. 외부 레포로 분리 + **관문 1개(G3, main 직전)** + **명세 기반 공격 1종(속성기반)** → 한 프로젝트에 **비-LLM 우선, 리포트만**(이빨 없이) PoC.
5. 이빨 부착 — GitHub Actions 필수 체크(중지) → 배포 웹훅(롤백).
6. 공격 도구 확장(퍼즈·차등·프로빙) + 4관문 완비.
7. 자기진화(화이트리스트 수집기 + 사람 승인 + 전문가 피드) + **감시자 자기감사**.
8. 다른 벤더 공격자 + 크로스프로젝트 등록.

원칙: 매 단계 실측 검증, 시각/파괴적 자동 금지, 상시 감시 비용은 on-demand 우선.

## §6. 정직한 한계
- **상관된 맹점**(§1-4): 완전 극복 불가. 비-LLM 검사가 1차 방어, 다른 벤더가 2차. "예측 못 한"은 체계적 축소가 최대치.
- **감시자 자신의 부패**: ②도 썩는다 → 자기감사 재귀 필수.
- **롤백의 현실**: 자동 롤백은 상태 있는 시스템(DB 마이그레이션 등)에선 위험 — G2·G4는 "롤백 명령"이되 파괴적 되돌림은 사람 확인 경유 권장(Doc 파괴적 작업 사전확인 원칙).
- **비용 절제**: 4관문 상시 + 다른 벤더는 토큰. self-host+결정론 우선으로 억제, LLM은 필요할 때만.
- **완성은 없다**: 확률적 대상은 완전 결정화 불가(방법론 자인). 이 문서도 설계도지 완성품이 아니다.
