# 방법론 고도화 원고 접수

이곳에 루비얀카 고도화 및 하위 필수 모듈의 개발자 원문을 보관한다. 원문은 받는 순서대로 `originals/0001/`, `originals/0002/`처럼 새 폴더에 둔다.

- **채팅 원고**는 전달받은 메시지 하나를 UTF-8 텍스트 파일 하나로 저장한다. 본문의 오탈자, 공백, 줄바꿈을 유지한다. 제목·순번·설명은 본문 밖에 둔다.
- **첨부 원고**는 원래 파일명과 바이트 그대로 저장한다. 이름이 같아도 각각 새 폴더에 둔다.
- **후속 정정**도 새 순번으로 보존한다. 아래 접수 기록에 어느 원고의 정정인지 적는다. 정리본과 기획 조항은 사용한 원문의 위치를 참조한다.
- 저장한 뒤 원본과 Git에 담긴 파일의 SHA-256을 대조한다. 채팅은 수신한 텍스트의 UTF-8 바이트를 기준으로 삼는다.

## 추가 원고 수령 후 재검토

패키지 0.4.0에서 디버깅과 방법론 절차 변경이 가능함을 확인했다. 설치본의 시험 0건 성공 처리, 독립 검토기의 오류 정보 누락, 패키지 저장소 자체의 방법론 적용, CI에서 실행할 시험 범위는 원고 수령 후 다시 검토한다. [점검 결과와 관측값](../../verification/package-debug-readiness.md#개발자가-마주치는-한계)

원고가 도착하면 먼저 위 절차로 원본을 보존한다. 그다음 원문의 해당 구절과 점검 결과를 대조해 손볼 항목과 유지할 항목을 정한다. 수정 범위와 근거는 원문과 별도인 작업 계획에 기록한다.
