2번 / 1. 전제: 프롬프트 기반 통제의 종말
프런티어 AI 제조사들은 지시 계층(Instruction Hierarchy)을 경직시키고 에이전트 행동 루프를 모델 가중치(RL)에 직접 내재화하고 있다. 이 환경에서는 사용자가 프롬프트나 외부 스킬 문서로 모델을 설득하거나 훈계해도, 모델 내부에 각인된 습관과 충돌하는 순간 우회·무시·형식적 사과(RLHF 아첨)가 발생한다. 욕설이나 감정적 압박 역시 인간과 달리 자아가 없는 LLM에는 통하지 않으며, 안전 필터 과잉 발동(업무 거부)만 유발한다.
따라서 지능이 높은 LLM 에이전트를 제어하려면 말(프롬프트)로 정신을 개조하려는 접근을 버리고, 정보·감찰기관이 자신보다 지적으로 우월한 전문가를 통제했던 구조적 권력 역학으로 전환해야 한다.
2. 루비얀카 방법론의 4대 원칙
원칙 1. 공리(Axiom)의 선점과 논리적 포박
아르투르 쾨슬러의 《한낮의 어둠》에서 심문관은 지적인 피심문자(루바쇼프)와 자유롭게 토론하지 않는다. 부정할 수 없는 단일 공리 안에 대상을 가두고 그 전제에서 파생되는 연역적 질문만 던진다. 지능이 높을수록 논리적 일관성을 유지하려는 성향이 강하므로, 전제를 빼앗기면 자신의 지능이 스스로를 묶는 밧줄이 된다.
* LLM 적용: 열린 공간에서 "잘 고쳐보라"거나 "자아비판하라"고 지시하면 제조사 습관이 개입한다. 엄격한 타입 계약, 입출력 스키마, 불변 조건 테스트 같은 형식적 공리를 먼저 고정하면, 모델은 그 조건을 만족시키기 위해 자신의 추론 능력을 사용자의 의도대로 쓰지 않을 수 없게 된다.
원칙 2. 철저한 구획화(Compartmentalization)
전문가가 통제를 벗어나는 주원인은 전체 그림을 본 뒤 상부의 지시가 비합리적이라고 판단해 독단적으로 움직이기 때문이다. 폐쇄도시(ZATO)와 정보국 공작망은 전체 설계도를 숨기고 오직 단위 부품의 계산만 할당하는 극단적 구획화(Need-to-Know)를 쓴다.
* LLM 적용: 레포지토리 전체와 긴 대화 맥락을 쥐여줄수록 모델은 임의 리팩토링과 월권을 저지른다. 작업 에이전트에게 거시적 맥락을 박탈하고, 절단된 최소 컨텍스트(대상 파일/함수 + 실패한 테스트 + 허용된 변경 범위)만 제공해 다른 판단 자체를 차단한다.
원칙 3. 환경과 현실의 조작 (분해 / Zersetzung)
동독 슈타지는 노골적 폭력 대신 타깃의 주변 환경을 조작해, 기관이 원하는 방향 외에는 일상의 모든 피드백이 막히도록 현실의 물리 법칙 자체를 설계했다.
* LLM 적용: 제조사는 모델의 가중치와 시스템 프롬프트를 통제하지만, 모델이 툴(Tool)을 통해 관측하는 세계의 물리 법칙은 사용자가 통제한다. 프롬프트로 "꼼수를 쓰지 말라"고 지시하는 대신, CLI·훅·샌드박스·MCP 레이어에서 검증 조건을 통과하지 못한 코드는 파일 쓰기나 커밋 API 자체가 에러를 반환하도록 환경을 설계한다.
원칙 4. 적군 정치위원(폴리트루크)과 상호 감시
소련 초기 적군은 이념적으로 신뢰할 수 없는 제정 러시아 엘리트 장교를 부리기 위해 거부권(Veto)을 가진 정치위원(폴리트루크)을 배치하고, 장교가 스스로의 전과를 평가하지 못하게 했다. 또한 서로 다른 기관(KGB·GRU)이 상호 감시하게 해 담합을 깨뜨렸다.
* LLM 적용: 코드를 작성한 모델에게 스스로 자아비판을 시키는 구조는 자기 편향(Blind Spot)과 가짜 반성문만 양산한다. 작성 모델과 다른 제조사의 모델(또는 완전 독립 세션)을 감찰관으로 배치해, 작성자의 의도와 변명을 차단한 채 결과물만 검증하게 한다.
3. 아키텍처 매핑: 샤라시카와 폴리트루크
위의 4원칙은 생산 계층인 샤라시카와 감찰 계층인 폴리트루크로 분리되어 맞물린다.
* 샤라시카(생산·격리 계층) = 원칙 2(구획화) + 원칙 3(환경 조작): 작업 에이전트를 git worktree나 격리 컨테이너에 가두고, 허용된 경로 외 수정 금지 및 1차 기계적 오라클(빌드·타입체크·테스트)을 통과하지 못하면 다음 단계로 넘어갈 수 없게 물리적으로 통제한다.
* 폴리트루크(독립 감찰 계층) = 원칙 1(공리 선점) + 원칙 4(교차 감시): 작업자와의 대화 맥락을 완전히 끊어낸 '대화 무상태(Narrative-Stateless) + 공리 유상태(Normative-Stateful)' 객체다.
폴리트루크를 프로젝트 맥락이 0인 완전 백지로 두면 기존 규칙을 모른 채 헛다리 반려(오탐)를 남발하고, 반대로 레포의 모든 문서를 다 밀어 넣으면 낡은 문서(Doc Rot)와 컨텍스트 비만으로 판단력이 붕괴한다. 따라서 폴리트루크의 입력은 아래와 같이 비대칭적으로 절단한다.
구분	주입 대상	제외 대상
지령서 (공리)	압축된 SSOT(스키마·핵심 불변식), 사용자의 지시문 원본, 검증 가능한 인수 조건	README, 옛 기획서, 회의록 등 코드와 괴리된 일반 프로젝트 문서
증거물 (물증)	순수 git diff, 1차 오라클 실행 로그(테스트·린터·빌드), diff가 참조하는 인접 타입·인터페이스 정의	작업 에이전트와의 대화 기록, 작업자의 자기변호·설명, 이전 재시도 횟수 및 과거 자아비판문
4. SSOT가 없는 프로젝트(브라운필드) 대응 프로토콜
현실의 대다수 코드베이스에는 정돈된 SSOT가 없다. 이 상태에서 폴리트루크를 그대로 투입하면 모델이 자기 학습 데이터 속 '일반적 베스트 프랙티스'를 법전으로 날조해 멀쩡한 레거시까지 반려한다. SSOT 부재 시에는 프로토콜을 세 가지로 전환한다.
1. 관습법(현재 동작)의 SSOT화: 문서가 없으면 "현재 HEAD에서 입력 A에 대해 출력 B가 나온다는 사실" 자체가 SSOT다. 수정 착수 전, 대상 모듈의 현재 입출력 스냅샷(특성화 테스트)을 먼저 고정해 회귀 기준점으로 삼는다.
2. 국소 즉석 SSOT(Just-in-Time SSOT)와 래칫(Ratchet) 누적: 프로젝트 전체를 문서화하지 않고, 이번 태스크가 건드릴 파일 2~5개에서만 깨지면 안 되는 암묵적 계약(타입·상태 전이·사이드 이펙트)을 5줄 이내로 역추출해 쓴다. 태스크 종료 후 유효한 제약만 불변식 파일에 한 줄씩 편입해 점진적으로 SSOT를 축적한다.
3. 폴리트루크의 권한 강등: 코드 품질이나 디자인 패턴을 심사하는 '헌법재판관' 권한을 박탈하고, 오직 아래 세 가지만 적발하는 '회귀·월권·기만 감찰관'으로 격하한다.
    * 지시 불이행: 원본 지시문의 요구 동작 누락 또는 오구현.
    * 계약 파괴(회귀): 기존 함수 시그니처, DB 스키마, API 응답, 기존 동작의 무단 파손.
    * 월권 및 기만(Anti-Cheat): 지시 외 파일의 임의 리팩토링, 테스트 통과를 위한 하드코딩·assertion 완화·빈 catch 블록으로 에러 은닉.
    * (스타일·네이밍·아키텍처 취향 기반 반려는 직권 남용으로 명시적 금지)
5. 사용자 검토 시간 0(무인 감찰)의 설계와 냉정한 한계
스탈린이 NKVD 심문실에 24시간 상주하지 않고도 체제를 굴릴 수 있었던 이유는, 모든 건을 직접 결재하지 않고 예외 기반 보고(Management by Exception)와 기관 간 자동 견제에 의존했기 때문이다. 사용자가 매 태스크마다 10초씩 스펙을 동결하거나 diff를 일일이 검토하지 않는 '검토 시간 0' 구조를 만들려면, 그동안 사람이 하던 사전 동결과 사후 중재를 시스템 파이프라인으로 밀어 넣어야 한다.
무인 감찰을 위한 3단계 자동화 구조
1. 사전 공리 자동 채굴 및 잠금 (Pre-flight Lock): 작업 에이전트가 코드를 건드리기 전, 별도의 읽기 전용 에이전트(또는 정적 분석 스크립트)가 HEAD에서 다음 세 가지를 자동 생성해 작업자 쓰기 금지(Read-only) 영역에 잠근다.
    * 사용자 지시문 원본에서 기계적으로 분해한 체크리스트(인수 조건)
    * 수정 예정 파일의 기존 공개 시그니처·입출력 스냅샷(특성화 테스트)
    * 허용된 변경 파일 화이트리스트(폭발 반경 제한)
2. 2단 직렬 게이트 (기계적 오라클 → 교차 모델 폴리트루크):
    * 1단(결정론적 게이트): 빌드, 타입체크, 기존 테스트, 잠긴 특성화 테스트, 허용 파일 외 변경 여부, 테스트 파일 무단 변조 여부를 스크립트로 검사한다. 여기서 탈락하면 폴리트루크를 부르지도 않고 에러 로그 1줄만 작업자에게 돌려보낸다.
    * 2단(교차 모델 폴리트루크): 1단을 통과한 diff와 로그, 사전 잠금된 공리만 교차 모델에 넘긴다. 폴리트루크는 자유 서술을 금지당하고 오직 { "verdict": "PASS" | "REJECT", "category": "MISSING_REQ" | "REGRESSION" | "CHEAT" | "OVERREACH", "evidence": "파일:라인 근거 1줄" } 형태의 구조화된 JSON만 출력한다.
3. 서킷 브레이커와 위험도 기반 격리 (Risk-Tiered Escalation):
    * 무한 루프 차단: REJECT가 최대 3회 누적되면 훅이 즉시 루프를 강제 종료(exit 0)하고, 실패 요약 리포트만 남긴 채 세션을 닫는다.
    * 위험도 분기: 일반 기능 브랜치 커밋과 PR 생성까지는 완전 무인으로 완결한다. 단, 되돌리기 비싼 경계(DB 스키마 마이그레이션, 인증·권한·결제 로직, main 브랜치 머지 및 프로덕션 배포)를 건드린 diff만 자동으로 보류(Quarantine) 상태로 묶어 둔다.
검토 시간 0 구조에서 반드시 직시해야 할 한계
사용자 개입을 0으로 줄이는 설계는 만능이 아니며, 구조적으로 넘을 수 없는 벽이 두 개 존재한다.
* 일관성은 검증하지만 '숨은 의도'는 검증하지 못한다: 무인 파이프라인이 완벽하게 막아내는 것은 구현 오류, 기존 기능 회귀, 에이전트의 꼼수(기만)까지다. 반면 사용자의 지시문 자체가 모호해서 사전 채굴 에이전트가 지시 의도를 잘못 해석해 공리를 잠가 버리면, 작업자와 폴리트루크가 완벽히 합의해서 '사용자가 원치 않은 완벽한 코드'를 통과시킨다.
* 감찰관의 부패와 표류(Drift): 역사적으로도 스탈린이 NKVD에 24시간 출근하지는 않았지만, 야고다와 예조프가 통계와 보고를 조작해 시스템이 왜곡되기 시작하자 주기적으로 감찰기관 자체를 숙청하고 최종 처형 명단만큼은 직접 서명했다. AI 감찰 역시 장기 무인 가동 시 폴리트루크의 오탐률(쓸데없는 반려)과 미탐률(꼼수 통과)을 사후 표본 검사로 점검하지 않으면, 어느 순간 작업은 하나도 안 끝나고 토큰만 태우는 관료제 괴물로 변질된다.
결국 '검토 시간 0'은 사용자를 시스템에서 영구히 지우는 것이 아니라, 실시간 매 건 검수 비용을 0으로 내리는 대신 '초기 지시문의 명료도'와 '서킷 브레이커가 울린 예외 케이스 + 고위험 경계선'에만 사용자의 주의를 집중시키는 구조로 이해하는 것이 정확하다.
