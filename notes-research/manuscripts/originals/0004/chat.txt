0. 지시 계층 (Control Plane — 사용자 영역)
* 세션 정책: 실행 파이프라인 외부에 존재한다. 사용자가 요구사항을 구상하거나 지령을 작성하는 환경이며, 실제 코드를 수정하는 워커 세션과 컨텍스트를 공유하지 않는다.
* 관리 지침:
    * 프로젝트 시작 시 불변 규칙(gost.json)과 최초 시각 SSOT(디자인 토큰·기준 스크린샷)를 1회 동결한다.
    * 작업 지시는 줄글이 아니라 번호(1., 2., 3.)로 구분된 원자 항목으로 orders.md에 기록한다.
    * 실시간 매 건 검수나 워커 설득을 수행하지 않으며, 오직 서킷 브레이커로 격리된 태스크(QUARANTINED)와 고위험 경계선(DB 마이그레이션, 인증·결제, main 머지 및 배포)만 최종 승인한다.
1. 고스플란 (Gosplan — 계획·원자화·공리 잠금)
* 세션 정책: 무세션(LLM 개입 0%). 오케스트레이터 및 결정론적 파서 스크립트로 실행한다. 단, SSOT가 없는 브라운필드 레포에서 수정 대상 파일의 암묵적 계약(타입·입출력)을 사전 채굴할 때만 읽기 전용 원샷 탐색기를 보조 호출하며, 이 경우에도 원문 지시 편집 권한은 0으로 제한한다.
* 접근 권한 및 경계: orders.md, gost.json, 대상 레포지토리를 읽고 ledger.json과 lock/<TASK-ID>/를 생성한다. 작업 브랜치의 소스 코드는 수정하지 않는다.
* 관리 지침:
    * 1:1 무손실 분해: orders.md의 최상위 번호 항목 수와 ledger.json 태스크 수는 반드시 일치해야 한다. 파싱 실패 시 추측하지 않고 즉시 exit 1로 중단한다. 항목의 병합·삭제·임의 요약 기능을 구현하지 않는다.
    * 직렬 배차 락: 선행 태스크가 DONE 상태에 도달하기 전에는 후속 태스크의 샤라시카 세션을 생성하지 않는다.
    * 상시 칙령 자동 주입: gost.json에 정의된 방식 제약(method_locks), 금지 편법(forbidden_shortcuts), 보호 경로(protected_paths), 시각 토큰을 모든 태스크 카드에 자동 병합한다.
    * 사전 잠금 봉인 (lock/<TASK-ID>/): 워커 스폰 직전에 ① 사용자 원문 지시 발췌본(raw_order.txt), ② 허용 수정 파일 화이트리스트(scope.json), ③ 보호 파일 SHA-256 해시(protected_hashes.json), ④ 브라운필드 특성화 스냅샷을 작업자 쓰기 금지 영역에 고정한다.
    * 항명 분리 규약 삽입: 비정형 요구사항에 INTENTIONAL_CONSTRAINT 플래그를 부여하고, 워커의 기술적 반론은 구현 변경이 아닌 dissent_log 기록으로 분리하도록 태스크 계약에 명시한다.
2. 샤라시카 (Sharashka — 격리·생산·경쟁·숙청)
* 세션 정책: 일회용 원샷 세션 (Spawn → Kill). TASK-ID 1건당 비대화형 헤드리스(Headless) 자식 프로세스를 신규 생성한다. 세션 재개(Resume), 스레드 유지, 실패 세션에 대한 멀티턴 설득(교화)을 전면 금지한다. 작업 완료 또는 반려 즉시 프로세스와 메모리 내 대화 컨텍스트를 파기한다.
* 접근 권한 및 경계:
    * 전용 git worktree 또는 샌드박스 컨테이너 내부에 물리적으로 격리한다.
    * 레포지토리 전체 잡문서와 이전 태스크의 대화 로그를 차단한다. 오직 할당된 단일 태스크 카드, 상시 칙령, scope.json 범위 파일만 참조한다.
    * lock/<TASK-ID>/, 보옌프레드 스크립트, 보호된 테스트 스위트 및 설정 파일에 대한 쓰기 권한을 툴·권한 레벨에서 차단한다.
* 관리 지침:
    * 단일 과업 집중: 할당된 TASK-ID 외 주변 파일의 임의 리팩토링, 포맷팅, 기능 추가를 금지한다.
    * 방식 잠금 및 안티스텁 준수: 목표 달성뿐 아니라 method_locks를 준수해야 하며, 하드코딩·더미 반환·우회 렌더링(예: 2D 픽셀의 UIKit/DOM 노드 구현)을 금지한다.
    * 이견과 실행의 분리: 기술적 이견이 있어도 요구사항을 임의로 순화하거나 축소하지 않는다. 이견은 dissent_log에 1줄로 기록하되 구현은 원문 지시대로 수행하며, 문법적·물리적 실행 불가 시에만 ABORT를 반환한다.
    * OKB 병렬 경쟁 (고위험 태스크 선택 적용): 난도가 높거나 실패 임계치가 낮은 핵심 태스크는 복수의 독립 워크트리(또는 이종 모델)에 동일 지령을 병렬 스폰해 검증 승자 브랜치만 채택하고 패자 워크트리는 즉시 삭제한다.
    * 즉각 숙청 (Kill & Respawn): 보옌프레드 또는 폴리트루크에서 REJECT 판정을 받으면 기존 세션을 이어서 수정하지 않는다. 해당 세션과 워크트리를 즉시 폭파·롤백하고, 직전 실패 근거 1줄만 금지 제약으로 추가해 완전히 깨끗한 새 세션을 스폰한다.
3. 보옌프레드 (Voenpred — 기계적 실사용 게이트)
* 세션 정책: 무세션(LLM 개입 0%). 100% 결정론적 CLI 스크립트 및 테스트 러너로 실행한다. 언어적 해석이나 추론 모델을 일절 호출하지 않는다.
* 접근 권한 및 경계: 샤라시카 워크트리, 고스플란 잠금 폴더(lock/<TASK-ID>/), 독립 검증 스위트를 읽기 전용으로 참조한다. 소스 코드를 자동 수정하지 않으며 판정 결과(voenpred_report.json)만 기록한다.
* 관리 지침:
    * Fail-Closed 절대 원칙: 기본 판정은 무조건 REJECT다. 타임아웃, 파일 누락, 파싱 오류, 예상치 못한 예외 발생 시 경고(WARN)로 강등해 통과시키지 않고 즉시 exit 1을 반환한다. 스크립트 내부에서 종료 코드를 무시하는 || true나 빈 catch 블록을 전면 금지한다.
    * 4단 직렬 게이트 (실패 시 즉시 중단):
        1. 범위 및 변조 게이트 (TAMPER): git diff --name-only의 scope.json 이탈 여부 및 protected_hashes.json 해시 무결성 대조.
        2. 정적 안티치트 게이트 (ANTI_CHEAT): diff 추가 라인(+)만 스캔해 빈 catch {}, @ts-ignore/eslint-disable/noqa 무단 추가, test.skip/xit, gost.json 금지 패턴 위반 적발.
        3. 빌드 및 오라클 게이트 (BUILD / ORACLE): 타입체크, 빌드, 사전 잠금된 독립 테스트 및 브라운필드 특성화 스냅샷 실행. 작업자가 임의로 추가한 테스트의 통과는 완료 근거로 인정하지 않는다.
        4. 런타임 수치 게이트 (METRICS, 해당 태스크 한정): E2E 스모크, 뷰/DOM 노드 수 상한, 프레임 타임(예: 60fps) 등 정량 기준 검증.
    * 서명 없는 전이 차단: voenpred_report.json의 verdict가 PASS가 아니면 폴리트루크 호출과 고스플란 원장 상태 전이를 물리적으로 차단한다.
4. 폴리트루크 (Politruk — 교차 독립 의미·시각 감찰)
* 세션 정책: 일회용 원샷 세션 (Spawn → Kill). 보옌프레드 PASS 직후 샤라시카 작업 모델과 다른 제조사의 모델(불가 시 완전 격리된 독립 프로세스)로 신규 생성한다. 구조화된 JSON 판정 출력 직후 세션과 컨텍스트를 즉시 파기한다.
* 접근 권한 및 경계 (대화 무상태 + 공리 유상태):
    * 필수 주입 대상: 사용자 원문 지시(raw_order.txt), 고스플란 태스크 카드 및 상시 칙령(gost.json), 압축 SSOT, 순수 git diff, voenpred_report.json, diff가 참조하는 인접 타입·인터페이스 정의, UI 태스크 시 실제 렌더링 캡처와 기준 스크린샷.
    * 절대 차단 대상: 샤라시카의 대화 로그, 작업자의 자기변호 및 구현 설명 텍스트, 재시도 횟수 및 과거 실패 이력, 코드와 괴리된 일반 문서(README, 옛 기획서, 회의록).
    * 권한: 코드 및 파일 수정 권한 0(완전 읽기 전용).
* 관리 지침:
    * 원문 직조 의무: 고스플란 태스크 카드뿐 아니라 raw_order.txt를 직접 대조해 지시 누락(MISSING_REQ)과 의도적 축소 해석(SCOPE_SHRINK)을 적발한다.
    * 브라운필드 직권 남용 금지: SSOT가 없는 프로젝트에서는 코드 스타일, 네이밍, 디자인 패턴 취향 기반의 반려를 금지한다. 오직 지시 불이행, 기존 계약 회귀(REGRESSION), 허용 외 월권(OVERREACH), 기만(CHEAT)만 반려 사유로 인정한다.
    * 시각 이탈 감찰: UI 태스크는 주관적 미감 평가가 아니라 동결된 디자인 토큰과 기준 스크린샷 대비 레이아웃 붕괴·텍스트 잘림·토큰 외 임의 스타일 사용(VISUAL_DRIFT)만 판정한다.
    * 출력 형식 강제: 자유 서술을 금지하고 아래 JSON 스키마만 출력한다. 스키마 파싱 실패 시 Fail-Closed 원칙에 따라 REJECT로 처리한다.{
    *   "verdict": "PASS | REJECT",
    *   "category": "NONE | MISSING_REQ | SCOPE_SHRINK | REGRESSION | CHEAT | OVERREACH | VISUAL_DRIFT",
    *   "evidence": "파일경로:라인번호 - 위반 근거 1줄"
    * }
    *  
5. 전 계층 공통 상태 전이 및 영속화 규약
* 휘발성 메모리 파기와 디스크 영속화: 세션 간 대화 히스토리는 절대 승계하지 않는다. 태스크 종료 후 디스크에 남기는 영속 상태는 오직 ① 머지된 HEAD 코드, ② ledger.json 상태 및 변경 파일 경로, ③ 유효성이 확인되어 gost.json에 1줄 승격된 신규 불변식뿐이다.
* 단방향 상태 머신: 각 태스크는 PENDING → IN_PROGRESS → VOENPRED_PASS → POLITRUK_PASS → DONE 순서로만 전이한다. 중간 게이트 실패 시 PURGED로 기록하고 재시도 카운터를 증가시킨다.
* 서킷 브레이커: 동일 태스크에서 PURGED가 최대 3회 누적되면 오케스트레이터는 루프를 강제 종료하고 상태를 QUARANTINED로 동결한 뒤, 누적된 evidence 3줄만 요약해 사용자에게 에스컬레이션한다.
* 사보타주 레드 테스트(Red Test) 의무: 고스플란과 보옌프레드 구현 완료 시 정상 코드 통과 테스트만으로 완료를 인정하지 않는다. 의도적으로 화이트리스트 외 파일 수정, 보호 파일 1바이트 변조, 빈 catch {} 삽입, 번호 누락 파싱을 주입했을 때 시스템이 실제로 exit 1과 REJECT를 반환하는지 검증하는 사보타주 테스트를 필수 포함한다.
