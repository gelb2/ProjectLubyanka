5번 / 반려 루프 및 제로베이스 폴백 프로토콜 (Fallback & Zero-Base Rebuild)
본 프로토콜은 3단계(보옌프레드) 또는 4단계(폴리트루크)에서 REJECT 판정이 발생했을 때, 1단계(고스플란)와 2단계(샤라시카)로 되돌아가는 반려 간선(Edge)의 실행 규약이다. 별도의 추론 에이전트를 추가하지 않고 오케스트레이터 스크립트가 100% 결정론적으로 집행한다.
1. 실패 등급 분기 (Patch 허용 vs 즉시 제로베이스 파기)
모든 실패에 제로베이스 롤백을 일괄 적용하지 않고, 반려 사유 코드에 따라 처리 경로를 두 가지로 강제 분기한다.
* 경미한 국소 결함 (1회 한정 국소 수정 허용):
    * 대상: 보옌프레드의 단순 구문 오류, 누락된 import, 단순 타입 오타(BUILD 게이트 단일 실패).
    * 처리: 동일 워크트리를 유지한 채 최대 1회 수정 실행을 허용한다. 단, 1회 수정 후에도 동일 게이트를 통과하지 못하면 즉시 2등급(구조적 실패)으로 승격한다.
* 구조적 오염 및 기만 (즉시 제로베이스 파기):
    * 대상: TAMPER(보호 파일 변조), ANTI_CHEAT(꼼수 적발), SCOPE_SHRINK(축소 해석), OVERREACH(월권), VISUAL_DRIFT(시각 이탈), ORACLE(핵심 로직 실패), 또는 국소 수정 1회 초과 실패.
    * 처리: 기존 코드와 세션을 단 한 줄도 보존하지 않고 즉시 아래의 3단계 파기·재구축 절차를 실행한다.
2. 제로베이스 파기 및 재구축 3단계 절차
① 프로세스 강제 종료 및 워크트리 초기화 (Crash-Only Purge)
* REJECT 판정 즉시 현재 샤라시카 자식 프로세스를 강제 종료하고, 메모리 내 대화 히스토리와 임시 스레드를 완전 파기한다.
* 작업 워크트리에 git reset --hard HEAD 및 git clean -fd를 실행해 이전 시도의 코드 변경분과 생성된 임시 파일을 물리적으로 삭제한다.
* 오케스트레이터는 기존 세션을 재개(Resume)하거나 실패한 diff를 수정하도록 유도하는 복구 루틴을 일절 구현하지 않는다.
② 실패 원인 3줄 압축 및 금지 공리 누적 (Anti-Prior Injection)
* 보옌프레드(voenpred_report.json) 또는 폴리트루크(politruk_verdict.json)의 실패 근거에서 장황한 로그와 기존 diff를 제거하고, 아래 3개 필드만 추출해 lock/<TASK-ID>/anti_priors.json 배열에 누적(Append)한다.{
*   "attempt": 1,
*   "rejected_prior": "실패를 유발한 기존 구현 접근법 1줄 요약",
*   "refutation_evidence": "실패 게이트 코드 및 실측 수치·파일:라인 근거 1줄",
*   "hard_ban": "다음 시도에서 영구 금지할 구현 방식 1줄"
* }
*  
* anti_priors.json은 작업자 쓰기 금지 영역에 보관하며, 태스크가 DONE 또는 QUARANTINED로 종료될 때까지 이전 시도의 금지 조항을 삭제하지 않는다.
③ 백지 새 세션 스폰 (Clean-Room Respawn)
* 오케스트레이터는 초기화된 워크트리 위에 완전히 새로운 비대화형 원샷(Headless One-shot) 샤라시카 프로세스를 생성한다.
* 새 세션의 0턴 입력에는 오직 ① 고스플란 원본 태스크 카드 및 상시 칙령(gost.json), ② 최신 HEAD 기준 대상 파일, ③ lock/<TASK-ID>/anti_priors.json만 주입한다.
* 오염 차단 절대 규칙: 이전 시도의 코드 diff, 에러 전체 스택트레이스, 이전 작업자의 대화 로그 및 변명 텍스트는 새 세션에 단 1바이트도 전달하지 않는다.
3. 폴백 에스컬레이션 사다리 및 서킷 브레이커
동일 모델의 가중치 편향으로 같은 실패가 반복되는 것을 막기 위해, 재시도 횟수에 따라 실행 모델을 단계적으로 전환한다.
1. 1차 시도 (attempt: 1): 기본 샤라시카 모델 실행 (순수 고스플란 지령만 투입).
2. 1차 폴백 (attempt: 2): 제로베이스 파기 후 동일 모델 신규 원샷 세션 실행 (anti_priors[0] 주입).
3. 2차 폴백 (attempt: 3): 제로베이스 파기 후 교차 제조사 모델로 샤라시카 워커 교체 실행 (anti_priors[0..1] 주입).
4. 3차 실패 (서킷 브레이커 발동): 동일 태스크에서 PURGED가 3회 누적되면 오케스트레이터는 루프를 강제 종료(exit 0)하고, ledger.json 상태를 QUARANTINED로 동결한다. 이후 누적된 anti_priors.json 3건만 요약해 사용자에게 출력한다.
4. 구현 시 금지 사항 (오케스트레이터 제약)
* 대화 승계 금지: 폴백 시 이전 에이전트 세션 ID를 재사용하거나 대화 배열을 이어 붙이는 코드를 금지한다.
* 로그 덤프 금지: anti_priors.json 생성 시 500자 이상의 원시 테스트 로그나 코드 블록을 통째로 복사해 넣는 구현을 금지한다.
* Fail-Closed 유지: git reset --hard 실패, anti_priors.json 쓰기 실패, 교차 모델 호출 실패 시 이전 상태를 재사용하지 않고 즉시 태스크를 QUARANTINED로 중단한다.
