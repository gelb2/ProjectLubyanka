# 고스플란 구현 계획

고도화 계획의 첫 생산 모듈이다. [원고 3](../manuscripts/originals/0003/chat.txt)의 무손실 원장·방법 잠금과 [원고 4](../manuscripts/originals/0004/chat.txt)의 사전 잠금·직렬 배차를 구현한다. 검토 구절이 적힌 문서의 존재만으로 사용자 요구의 보존을 판정했던 사례 때문에 실제 설치 CLI의 원문 바이트와 동시에 발급된 배차 건수를 검사한다. [상위 계획](../METHODOLOGY-UPGRADE-PLAN.md) · [공통 계약](../oracle-scaffold/pipeline.md)

- 입력은 관리자가 전달한 원문, GOST, 태스크별 허용 범위다. 범위는 계획 검토 결과를 기계가 운반할 수 있다. 구현자는 사용자 문장을 다시 쓰지 않는다. UTF-8, CRLF, 들여쓴 번호, fenced code, 마지막 개행이 없는 입력에서 연속하는 바이트 구간을 만든다. 번호 누락·중복·해석 불능은 발령 전에 거부한다.
- 기준 Git 커밋에서 보호 파일·읽기 전용 의존성·지정한 특성화 조건을 확보한다. 브라운필드의 관측기는 사용자가 관리하는 읽기 전용 기준 코드로 실행한다. 원문 지시·규칙·허용 경로·특성화 결과는 배차 전에 지문을 남긴다.
- 원장과 잠금은 작업 트리 밖 공용 Git 관리 디렉터리에 둔다. 새 판본은 임시 디렉터리에 완성한 뒤 비어 있지 않은 최종 판본 디렉터리로 원자적으로 이동한다. 같은 판본을 읽은 두 프로세스 중 하나만 게시할 수 있다. 게시 전 중단한 임시 파일은 현재 판정에 쓰이지 않는다.
- 설치 CLI에서 원문 재조립, 손상 입력의 종료 코드와 원장 불변, 동시 배차에서 단 한 건 허용, 기준 커밋 이동 거부를 시험한다. 다음 모듈이 제공할 실제 서명·병합 이전에는 앞 태스크를 DONE으로 바꾸는 수동 우회를 제공하지 않는다.
