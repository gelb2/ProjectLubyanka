# 폴리트루크 계획

보옌프레드 병합본 `9f65d3f`에서 시작한다. 원고 2·4의 독립 감찰과 개발자의 모델 배정 원칙을 따른다. 원문과 결과를 직접 비교하지 않고 체크리스트만으로 끝낸 사례를 반영한다.

- 실제 원문, 정본, 인접 타입, 순수 diff, 통과한 기계 관측만 새 세션으로 전달한다. 이전 설명과 횟수는 제외한다. 등록된 UI 태스크에는 보호된 기준 PNG와 같은 후보에서 실행한 렌더러의 PNG를 함께 전달한다.
- 정상 배정은 Codex 작업자와 Claude 감찰관이다. 실행할 수 없는 제공자는 사유를 남기고 교체한다. 같은 제조사가 두 역할을 맡아도 새 프로세스로 감찰한다. 정상 반려와 손상 응답으로 재배정할 수 없다.
- 근거가 해당 후보·기준의 실제 파일과 행 또는 캡처에 있는지 대조한다. 이전 영수증·빈 JSON·없는 행은 승인하지 않는다. 격리 시험 대역은 운영 감찰 서명을 만들 수 없다.
- 계획 시험에서 작은 덧셈 구현과 고장난 기준을 독립 Claude에 전달해 각각 PASS와 REJECT를 받았다. 한쪽 실행 파일을 숨긴 두 방향에서 실제 대체 모델을 호출했다. 별도로 생성한 파란 PNG를 Claude의 이미지 입력으로 전달해 색을 확인했다. [원고 4](../manuscripts/originals/0004/chat.txt) · [실행 계약](../oracle-scaffold/pipeline.md)
