# 생산자 자체 적용과 이식 계획

반려·정산 병합본 `734c36e`에서 시작한다. 생산자 저장소의 실행 정답을 기존 정답지에 등록하고 원문과 과거 요구를 보존한다. 새 후보는 정본 확인·설치본 단위 시험·Docker 통합·GitHub 풀 리퀘스트 검사를 거친다. 설치 성공만으로 동작을 보고한 과거 오류를 반영해 npm에 담긴 시험의 수와 실제 실패를 검사한다.

- 실제 CLI로 생산자용 정본·자아비판·실행 정답을 읽고 독립 계획 검사와 실제 코드 시험 결과를 대조한다. 원장 선별, 보옌프레드 검측, 폴리트루크 감찰과 병합의 전체 경로는 소형 캡션 프로젝트로 시험한다. 기존 앱의 기본 설정과 구판 기록은 기존 시험으로 다시 확인한다.
- 현재 Git의 참조 정리에서는 같은 커밋의 packed ref가 먼저 기록된 뒤 loose ref를 삭제한다. 같은 커밋을 명시해 실제 브랜치를 삭제할 때는 packed refs의 갱신 잠금이 있었다. 격리 저장소에서 정리·이름 변경·삭제를 각각 확인하고 보호 브랜치의 논리값을 보존한다.
- GitHub에서 develop·main의 출처 검사와 설치·통합 검사를 필수화한다. 원격에서 실제 PR의 검사·병합 결과를 확인한다. 프로젝트 설정에 로그인 토큰을 넣지 않는다.
- 첫 사용 앱은 바사리다. 생산자 검증과 실제 적용 앱의 설치·기능 결과를 따로 기록한다. [설립 정본](../../governance/PROJECT-CHARTER.md) · [패키지 자체 점검](../../verification/package-debug-readiness.md)
