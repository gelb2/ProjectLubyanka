# 0.5.0 실행 연결과 공개 계획

생산자 적용을 병합한 `c85625e`에서 출발한다. 캡션 예제에서 각 CLI를 순서대로 호출하면 검측 실패·재구축·공식 서명·병합까지 동작했다. 설치 사용자는 같은 순서를 단일 실행 명령으로 시작하고, 중간에 멈추면 원장에서 재개해야 한다. 실제 합격과 단순 설치를 혼동했던 사례 때문에 같은 main tarball에서 자동 시험과 실모델 예제를 모두 실행한다.

1. 원장의 현재 상태에서 다음 허용 단계만 실행한다. 폐기 후 재배차, 사용자 승인 대기, 격리와 종료를 구분한다. 승인한 규칙 승격과 격리 작업 재발령은 기존 원문과 판정을 보존한다. 관리형 훅이 있는 프로젝트에서 검측한 제안만 병합하도록 시험한다.
2. 관리형 훅을 연결한 실모델 시험에서 감찰 근거가 한 줄 좌표 검사를 통과하지 못했다. 실제 제공자와 반려 좌표를 진단에 남기고 허용 파일·행 표기를 감찰 입력에 명시한다. 같은 합격 조건으로 다시 시험한다. 공개 직전 원격 main의 부모·트리를 대조하고 tarball을 한 번 만든다. 같은 바이트의 빈 프로젝트 설치, 실제 Codex·Claude 캡션 예제, 기존 API와 회귀 시험 결과를 확인한다.
3. 공식 npm 게시·integrity가 확인된 뒤 바사리 전담 세션에 정확한 버전과 기존 로컬 설치 제거를 전달한다. 바사리가 공식 설치 검사를 통과했는지 별도로 확인한다. [공통 계약](../oracle-scaffold/pipeline.md) · [배포 절차](../../verification/README.md)
