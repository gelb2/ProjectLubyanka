# 샤라시카 구현 계획

고스플란 병합본 `933c380`에서 출발한다. [원고 4의 생산 계층](../manuscripts/originals/0004/chat.txt)과 [공통 계약](../oracle-scaffold/pipeline.md)에 따라 배차 1건을 새 프로세스에 전달하고 후보 트리를 회수한다.

- 관리자가 봉인한 원문·규격과 지정 파일만 준비한다. 모델의 결과는 허용 파일의 변경 제안과 이견 또는 ABORT다. 원장·검증기·저장소 전체를 워커에 마운트하지 않는다.
- 빈 작업공간에서 일회용 격리 프로세스를 실행한다. 관리자는 검토된 변경만 별도 Git 인덱스에 적용해 후보 트리를 만들고 시도·작업자·후보를 연결한다. 중복 실행은 원장 판본의 단일 게시로 막는다.
- 정상 변경과 다중 독립 후보, 보호 파일 수정 시도, 원문·잠금 변경, 이전 세션의 파일 유입을 검사한다. 격리 성공과 실제 모델 판단의 품질을 따로 기록한다. 거부권과 채택은 보옌프레드·폴리트루크 단계에서 시험한다.

개발자 후속 지시 원문은 “코덱스 작업자 클로드 감찰관 - 우선원칙이되 코덱스나 클로드 둘 중 하나가 동작하지 않으면 코덱스 혹은 클로드로 모델 할당 변경 가능”이다. 정상 응답의 반려와 실행 불가를 구분해 실제 배정을 기록한다.

초기 시험은 Linux의 모든 네트워크 장치 이름을 외부 연결로 해석해 실패했다. 같은 컨테이너에서 외부 주소 0개와 외부 라우팅 항목 0개를 확인했다. 이후 도구 권한, 읽기 범위와 실제 외부 연결 가능성을 각각 검사한다.
