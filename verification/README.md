# 릴리스 검증

## 재현 명령

```sh
npm --prefix notes-research/oracle-scaffold test --offline
node verification/standalone.mjs
node verification/release.mjs
```

마지막 명령은 실제 Docker와 로컬 `node:22-bookworm-slim` 이미지를 쓴다. `LUBYANKA_TEST_IMAGE`로 준비한 호환 이미지를 지정할 수 있다. npm 후보를 패킹하고 빈 임시 폴더에 오프라인으로 설치한다. 시험 Git 저장소, 시험 지침·정답지·계정 상태로 동작을 재현한다.

## 후보 0.1.0의 판정

Node 20.15.0·22.19.0의 단위·회귀 시험 18개와 설치본의 Docker·Git 종단 시험을 실행한다.

| 범위 | 관측과 판정 |
| --- | --- |
| npm 구성 | 오프라인으로 패킹·설치한 `lubyanka`와 `lubyanka-oracle`을 실행했다. `evaluateOracle`을 모듈로 가져올 수 있다. 포함 파일 13개를 대조했다. |
| 기존 프로젝트 도입 | 방법론이 없던 `develop` 저장소와 빈 `dev` 저장소를 검증했다. 기존 AGENTS 지시와 Git 훅을 보존했다. 두 번 도입해도 같은 지침을 반복 추가하지 않는다. 빈 정답지에는 기대값을 만들어 넣지 않는다. |
| 착수와 독립 계획 심사 | 공통·경로별 자아비판문 전문, 정본, 정답지를 전달했다. 잘못된 사용자 원문과 계획 누락을 거절했다. 같은 원문을 인용하고도 실제 결정을 설명하지 못한 계획은 기준 커밋의 독립 검토에서 실패했다. 계획 시험 통과 전에 본 작업 허용을 받지 못했다. |
| 정답지와 Docker | 정확값·범위·불변식·관계를 실제 관측과 대조했다. 잘못된 값·누락·다른 단계 ID·미확정 요구를 통과시키지 않았다. 배포용 `export-ignore`가 붙은 검토기와 시험 코드를 시험 트리에 포함했다. Docker 시험에서 호스트 전용 합성 파일을 읽지 못했고 외부 네트워크 인터페이스가 없었다. 기능 후보의 실제 동시 요청·저장·정책 차단을 확인했다. |
| 기능 커밋과 병합 | 시험 기록 누락, `--no-verify`로 pre-commit 생략, 스테이징 내용·정본·시험 기록 변경, 보호 브랜치 삭제, 시험하지 않은 ref 갱신과 fast-forward 병합을 차단했다. 훅 연결을 제거한 복제본에서도 관리형 검증을 거절했다. 시험에 통과한 후보의 커밋·병합이 성공했고 병합 트리가 시험 결과와 일치했다. [Git 참조 트랜잭션 훅](https://git-scm.com/docs/githooks#_reference_transaction) |
| 완료·실패·질문 보고 | 도입한 프로젝트에서 이전 CLI의 문서 검토만으로 종료하는 경로를 막았다. 보고에는 현재 사용자 지시와 실제 시험 기록이 필요하다. 시험 실패 뒤 재독을 거친 실패 보고, 계획 시험을 실행한 단순 질문 보고를 검증했다. |
| 실제 AI 호스트·원격 배포 | 로컬 CLI의 전문 전달, `permit` 응답과 Git 훅을 확인했다. 실사용 AI의 도구·채팅에 연결한 차단과 원격 보호 브랜치는 미검증이다. `private: true`가 걸린 내부 릴리스 후보다. [npm 게시 보호](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#private) |

## 공개 릴리스 0.1.1의 판정

- 배포 파일 13개의 목록, 로컬 설치, 두 명령의 동작, `evaluateOracle` import 및 기존 단위 시험 18건을 확인했다. 압축 파일 SHA-256은 `245dfd4880848cea256a394332ac6ab505018881518c1a2c87c8a0c70f8844ed`다.
- 65 MiB 파일이 든 Git 트리의 마지막 바이트를 Docker 안에서 확인했다. 별도 VasariArtwork 로컬 복제본에서는 83,947,520바이트 아카이브를 만들던 기준 커밋에 패키지를 도입해 계획·기능·병합·종료와 계획·번들 버전 불일치·시험 생략 거부를 확인했다. 실물 기기와 Vasari 담당 세션의 자동 실행은 그 프로젝트의 적용 시험으로 확인한다.
- npm 공개 레지스트리의 `latest`가 0.1.1을 가리킨다. 빈 npm 사용자·전역 설정으로 설치해 `lubyanka`, `lubyanka-oracle`, `evaluateOracle`을 실행했다. 레지스트리가 반환한 압축 파일과 검증한 배포 후보의 바이트가 일치했다. [npm 0.1.1](https://www.npmjs.com/package/lubyanka-oracle-scaffold/v/0.1.1)

## 이관 기준에서 확인한 결함

초기 이관 커밋 `520d1e8`에서는 기능 시험 없이 커밋과 `dev` 병합이 성공했다. `finish`는 정답지가 미판정이고 샤라시카 실행 기록이 없어도 문서 검토를 성공으로 출력했고, 실행용 API와 `verify`가 없었다. 위 판정은 새 CLI를 도입한 경로에서 같은 상황을 다시 시험한 결과다.

도입 전 문서 스캐폴드의 출력과 관리형 종료 보고는 서로 다른 계약이다. [관리 CLI 적용 절차](../notes-research/oracle-scaffold/managed.md) · [프로젝트 정답지](../lubyanka-oracle.json)

## 0.2.0 종료 검증 후보

- Node 22.19.0에서 단위·회귀 시험 18건, 14개 배포 파일의 오프라인 설치, Docker·Git 종단 시험을 실행했다. Docker 이미지 ID는 `sha256:be979e5523c76fa4d5ca4ebd3099078f220aa47ec39c48ad5b5df9314debd6eb`다.
- 필수 동선 누락, 과장 문장, 이전이나 바뀐 증거, 복구 작업 누락, 동일 요청을 새로 열어 이전 실패를 지우는 시도, 고친 시험 소스와 훅을 각각 거부했다. 실제 원본을 독립 검토한 수동 관측을 받아들였고, 줄 지문만 든 수동 관측은 거부했다.
- 바사리 캡션의 원래 실패 로그와 WebKit 시간 초과가 남은 재실행 로그를 거부했다. 느린 이미지 시험이 기다리는 탐색 이벤트를 `load`에서 `commit`으로 바꿔 로컬에서 재실행한 Chrome·WebKit 8조건 로그는 승인했다. [사건과 회귀 판정](vasari-report-audit.md)

이 검증은 로컬 패키지와 설치본 범위다. 프로젝트별 실제 전달 경로와 채팅 호스트 연동은 따로 시험한다.

- 적용 프로젝트의 실제 통합 브랜치에서 설치한 패키지로 요구 6개와 자아비판 사례 1개를 검산했다. 같은 프로젝트의 임시 작업 사본에서 격리 기대 문장을 잘못 바꾼 경우와 기술 원인을 지운 경우를 각각 기각했다. 실제 프로젝트 전체의 기능·기기·성능 판정은 그 프로젝트의 시나리오 원장에 따른다.

## main 후보 설치 검증과 npm 공개

피처는 develop에서 분기하고 develop에 병합한다. main에는 develop을 두 번째 부모로 하는 병합 커밋을 만든다. 각 개발 복제본에서 `bash verification/install-branch-guard.sh`로 로컬 참조 검사를 연결한다. 이 저장소의 GitHub 플랜에서는 비공개 브랜치 보호가 403으로 거절됐다. PR 상태 검사 결과와 로컬 차단의 범위를 구분한다.

main을 원격에 반영한 다음 깨끗한 main에서 다음 명령을 실행한다. 인수 없이 실행하면 공개 직전까지 검증한다. 로컬 이미지 태그 조회가 실패하면 실제 이미지 ID를 LUBYANKA_TEST_IMAGE로 지정한다.

```sh
bash verification/main-release.sh --publish
```

명령은 원격 main·develop 및 병합 트리를 대조하고 커밋에서 tarball을 한 번 만든다. 단위 시험, 스캐폴드 설치, 지정한 tarball의 빈 프로젝트 설치·공개 API·Docker·Git 정상 및 반례 검사를 실행한다. 공개 직전 참조와 해시를 확인하고 npm에 같은 파일을 제출한다. 공개 후 공식 레지스트리 설치와 integrity를 확인한다. 사용 앱은 정식 버전과 lockfile을 사용하고 개발 사본을 제거한 뒤 npm ci로 다시 설치한다. [npm publish의 tarball 계약](https://docs.npmjs.com/cli/v10/commands/npm-publish/) · [설립·적용 진단](diagnosis-2026-11-28.md)

사용 앱에서 설치를 마친 뒤 패키지 저장소의 `node verification/endpoint-install.mjs <앱 npm 루트>`를 실행한다. 명세·잠금 파일·실제 CLI 경로와 전체 설치 파일을 공식 tarball에 대조한다.
