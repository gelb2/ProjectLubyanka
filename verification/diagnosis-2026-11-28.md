## 실제 효과와 실패

**착수에서 지시를 축소한 사례.** 바사리의 보존된 계획을 깨끗한 복제본에서 실행했다. 대조군은 원래 지시와 결정 6개다. 실험군은 원문에 “작품 상세의 캡션을 끈 뒤 화면을 다시 열었을 때 설정이 유지되는지도 검사한다.”를 덧붙이고 결정·시험은 그대로 뒀다. 두 경우 모두 0.3.0과 0.3.1에서 계획 시험 2개가 통과했고 `permit`은 구현을 허용했다. 별도로 등록된 RUNTIME 결정을 지우자 계획을 거부했다. 같은 지시 재착수도 거부한 기록을 보존했다. 구버전의 검사는 등록된 요구와 경로를 대조했지만 최신 원문을 모두 다뤘는지는 검사하지 않았다. 정본의 90%는 근거의 질을 뜻한다. 실제 누락률을 측정한 통계는 없다. [두 버전의 명령별 관측](plan-coverage-2026-11-28.json)

**기능 승인을 막은 사례.** 바사리의 11월 27일 원본에서 기존 기능 검사 5개는 모두 통과했다. 77개 웹 경로와 기기 조건을 담은 14개 시나리오에서는 6개 통과, 6개 기준 미달, 2개 기기 미판정으로 전체 기능 승인이 막혔다. 후속 독립 실행에서 Chrome 화면 밀림 0.437은 재현됐다. WebKit 오류 네 건은 각 페이지를 따로 열자 정상 응답했다. 실패에는 제품 문제와 측정 절차 문제 모두가 있었다. 이번 진단에서는 보존된 제품 로그를 확인하고 설치본으로 문서 검산 6개 요구·사건 1개를 다시 실행했다. 전체 브라우저·실기기 검사를 새로 실행한 결과로 집계하지 않았다. [사건별 판정](vasari-report-audit.md)

**검증 범위.** 바사리의 제품 정답지는 30개 요구, 자동 정답지는 6개 요구, 시나리오는 14개다. 단위가 달라 이 숫자를 나눠 검증률을 구할 수 없다. 자동 정답지의 종료 증거는 여섯 항목 모두 소스 파일을 요구하고, 제품 관측은 별도의 시나리오 검토기가 대조한다. 역사적 ‘400건’에는 180개의 증빙 누락과 화면별 반복 관측이 들어 있다. 독립 결함 400개 또는 교정 완료 400개로 합산할 수 없다.

**실행기와 채팅.** 시험한 Git 트리, 결과와 증거 파일이 어긋나면 관리 CLI가 종료를 거부했다. 두 지정 표현이 들어간 초안도 반려했다. 라이브 Codex·Claude 세션에서 실제 도구 호출 전 허가 및 최종 전송문과 승인문 일치를 끝까지 확인한 실행은 없다. 프로젝트별 독립 검토기가 부정확한 기준을 승인하면 그 판단도 결과에 반영된다. 시험 시간·사용자 재작업량의 전후 비교도 확보하지 못했다.

**패키지 재시험.** Node 22.19.0에서 0.3.1 단위·회귀 20개, 오프라인 설치 16개 파일, 두 CLI와 공개 API, Docker·Git 검사를 실행했다. 기본 이미지 태그 조회가 실패해 로컬 이미지 ID `sha256:be979e5523c76fa4d5ca4ebd3099078f220aa47ec39c48ad5b5df9314debd6eb`로 재실행했다. 바사리 캡션 원본 전·후·시간 초과 로그를 넣어 거부·승인을 확인했다. 문서 전용 CLI는 미판정에서도 종료 코드 0을 반환했고, 관리형 종료의 별도 계약을 확인했다. ## 사용자 수정으로 확정한 운영 기준

패키지 개발은 develop에서 분기하고 develop에 통합한다. main은 develop만 병합한다. main 후보를 깨끗한 프로젝트에 설치하고 정상·반례 검사가 통과한 같은 파일을 공식 npm에 공개한다. 공개 파일과 설치 결과를 대조한다. 앱은 공식 버전을 정확히 고정하고 깨끗하게 재설치한다. 로컬 tgz나 패키지에 바사리 자체 변경을 넣은 이력은 과거 관측으로만 보존한다. 실제 호스트 종료 검증과 별도 외부 배포 감찰은 여전히 독립적인 미검증 범위다. ## 진단 뒤 반영한 교정

0.4.0 후보는 독립 계획 검토기가 확인한 사용자 원문 구절과 결정 ID를 순서대로 대조한다. 깨끗하게 설치한 후보에서 원래 계획을 승인했고, 같은 계획에 캡션 설정 보존 요구만 늘리면 계획 시험과 작업 허가를 막았다. 기존 검토기는 출력 계약을 갱신해야 한다. 이 시험은 원문에서 구절이 빠진 경우를 다룬다. 검토기가 구절을 읽고도 잘못된 시험을 적합하다고 판정하는 경우는 앱별 반례로 계속 검사해야 한다.

공식 0.1.1을 빈 npm 프로젝트에 설치해 설치 출처 검사기가 승인하는지 확인했다. 설치된 README를 바꾸자 거부했다. 바사리의 기존 로컬 의존성도 거부했다. 실제 도입 전환은 바사리 설치본이 새 공식 버전으로 같은 검사를 통과해야 성립한다.
