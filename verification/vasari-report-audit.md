# 바사리 사례로 점검한 루비얀카 종료 검증

바사리의 자아비판문, 400건 작업 검토, 패키지 0.1.1 전수진단, v17 판정, 공개 화면 집계, 스킬 호출 기록, Candidate 캡션 전후 로그를 대조했다. 400건에는 브라우저 표본과 비교표의 빈 칸이 포함된다. 다음 표는 반복된 보고 경로와 각 경로를 차단할 근거를 기록한다.

| 관측한 사건 | 0.1.1에서 허용한 경로 | 0.2.0에서 확인하는 조건 |
| --- | --- | --- |
| v17의 시각·레퍼런스·스킬 요구 누락. 기존 자동 판정은 격리·접근·업데이트·작품 목록·번들 다섯 항목에서 통과했다. v18은 작품 상세의 사전 항목 9개를 비교했다. 전체 조건 180건은 그 비교에 들어 있지 않았다. | 계획과 시험은 등록된 ID만 판정했다. 종료 주장의 범위와 실행 판정의 범위를 대조하지 않았다. | 기준 브랜치의 요구와 사례를 제거할 수 없다. 각 사례의 주장을 빠짐없이 등록하고 판정한다. 전체를 주장할 때는 화면·환경·기능의 모집단과 직접 검증 기록을 함께 요구한다. |
| 색·CSS 변화율과 접근 보호로 레퍼런스 충실도와 디자인 개선을 설명했다. 기존 확대 기능을 새 변경으로 적었다. | 자유 형식 종료 보고에 비교 대상과 판본을 묶지 않았다. | 독립 검토기가 전후 소스·시각 자료와 실제 동선을 본다. 변화율을 시각 판단과 별개로 요구할 수 있다. |
| 보관한 스킬 30개와 실행 기록을 혼동했다. 검토 시점 전용 호출은 0건이었고 BeUniq 실행은 4회, 결과는 2건이었다. | 스킬명이 적힌 기록과 실행을 구별할 근거 유형이 없었다. | 스킬별 착수·실행·결과를 `skill-run`에 연결한다. 원문 지문, 설치, 읽기, 실제 실행은 같은 증거로 처리하지 않는다. |
| 작품 정지 캡션을 Candidate의 시간차 전환으로 보고했다. 사용자 목록에서 직접 선택했을 때와 해설 응답이 실패했을 때를 놓쳤다. 버튼 표시만으로 클릭을 판정한 사례도 있었다. | 화면이 보이는지와 사람이 동작을 거쳤는지를 구별할 종료 조건이 없었다. | `motion`, `interaction`, `reference-source`를 사례별로 요구한다. 상태 전이·시점·눌렀을 때 결과·실패·복귀는 독립 검토기가 원본에서 판정한다. |
| MoMA에서 링크 목록과 캡처를 혼용했다. 문서 540개 중 537개에 방문·캡처가 있고 전체 공개 목록은 없다. 〈82nd & Fifth〉는 크기만 비슷한 6개 IPA를 미해결 후보로 올렸다. | 항목별 판정만 있고 모집단·파일의 정체성을 확인하는 관측을 요구하지 않았다. | `inventory`에는 모집단과 제외·누락을 둔다. `artifact`에는 실제 파일과 내부 식별값을 둔다. 목록, 메타데이터, 파일 입수는 각각 판정한다. |
| 보고서가 이전 후보를 표시했고 사용자가 받은 파일 링크는 HTML 편집기를 열었다. 시험한 제품과 당시 수신자가 열 수 있던 대상이 달랐다. | Git 후보 해시와 시험 결과는 연결했지만 보고서와 전달 경로는 확인하지 않았다. | 증거와 주장을 현재 작업·단계·후보 트리에 묶고 `delivery`에서 실제 수신 경로·빌드를 확인할 수 있다. 이전 증거의 해시가 일치해도 판본이 다르면 독립 검토가 반려한다. |
| 파일의 SHA나 소스 줄 지문을 만들고도 실제 분기 및 증거를 확인하기 전에 사용자에게 결과를 넘겼다. 실패를 발견한 뒤 바로 할 수 있는 재시험을 수행하지 않은 경우도 있었다. | 문서 읽기와 수정 상태에 대한 기록만 필요했다. 이전 실패의 내용을 지운 새 착수가 가능했다. 일반 판정에 수동 관측을 반영할 실행 경로가 없었다. | 주장에 붙인 파일을 열고 소스 바이트를 후보와 대조한다. `--manual-file`은 원본에 대한 독립 판정이 있어야 통과한다. 동일 요청의 미해결 실패를 새 착수로 덮지 못한다. 자아비판 뒤 이유·원인·후속 조치·실제 재시험 또는 확인한 제한을 요구한다. |
| 훅 복구가 파일이 삭제된 상태에서 성공을 반환했다. 시험 명령과 제품 소스가 같은 후보에서 실행되어 시험을 편집해 결과를 만들 수 있었다. | 훅 경로가 설정돼 있으면 설치를 건너뛰었다. 후보가 시험 소스를 바꾸는 경우를 별도로 검사하지 않았다. | 기존 훅 경로를 보존하고 삭제·교체를 탐지·복구한다. 등록한 시험 소스는 통합 브랜치의 바이트와 대조하고 독립 종료 검토기는 그 브랜치에서만 실행한다. |

위 조건은 프로젝트 정답지에 등록한 경우에 적용된다. 패키지는 현재 후보의 소스 바이트, 요구 범위, 증거 유형과 검토기 판정을 강제한다. 시각의 적절성, 외부 서비스의 실제 상태, 사람이 무엇을 읽었는지는 독립 검토기가 원본과 기준을 대조해 판단하는 영역이다. 연결된 호스트는 승인된 구조화 결과를 사용자 보고에 사용한다. 추가 검토 범위는 [적용 절차](../notes-research/oracle-scaffold/managed.md#02-종료-검증-도입)를 따른다.

## 재현

`node verification/release.mjs`는 npm 패킹·새 프로젝트 설치를 거쳐 실제 Docker와 Git에서 계획, 기능, 병합, 종료와 실패 경로를 실행한다. 응답 성공의 대조군과 함께 누락 동선, 이전 후보, 근거 파일 변경, 부풀린 문장, 실행하지 않은 교정, 시험 소스 변경, 수동 확인의 빈 선언을 넣는다. `LUBYANKA_VASARI_EVIDENCE`를 바사리의 비공개 증거 루트로 지정하면 실제 캡션 로그 세 개를 독립 검토기에 추가로 입력한다. 시험 데이터는 임시 프로젝트로 복사하고 완료 뒤 삭제한다.
